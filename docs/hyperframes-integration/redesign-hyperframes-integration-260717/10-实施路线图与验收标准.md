# 实施路线图与验收标准

## 本章目标

本章把前面章节转化为可执行的实施路线、任务拆分、测试范围和发布门禁。它可作为后续开发计划的直接输入。

## 分期策略

实施应按可发布的垂直切片推进，而不是按技术层横向铺开。

## 第一阶段：清单式项目目录基线

目标：保证 FreeCut 能保存、导入、导出和识别 HyperFrames 项目目录。

已具备基础：

- 清单式数据模型。
- 项目迁移。
- 项目目录存储。
- 双向转换器。
- Phase 1 验证测试。

还需补齐：

- 二进制资产复制。
- 项目打包和解包。
- 缩略图生成。
- 诊断在主界面显示。
- 源链接组合片段完整右键菜单。

验收：

- 普通项目无回归。
- 源链接组合可保存、关闭、重开。
- 项目目录缺失时有明确错误。
- 导入导出测试通过。

## 第二阶段：主界面源链接体验

目标：用户能在时间线中自然使用 HyperFrames 片段。

任务：

1. 时间线片段标识。
2. 属性面板。
3. 项目库页签。
4. 右键动作。
5. 选中片段预览。
6. 诊断显示。
7. 缓存状态显示。

验收：

- 用户可从项目库插入 HyperFrames 片段。
- 用户可双击打开工作室。
- 用户可查看源项目、诊断和来源。
- 删除、复制、修剪和移动行为符合 FreeCut 时间线语义。

## 第三阶段：内嵌工作室

目标：用户能在 FreeCut 主界面内编辑 HyperFrames 源项目。

任务：

1. 完善当前轻量工作室。
2. 接入安全文件读写。
3. 接入校验器。
4. 接入变量表单。
5. 接入缩略图。
6. 接入未保存提醒。
7. 评估并逐步替换为从 `packages/studio/src` 迁移后的 Studio 组件。

验收：

- 修改源文件后预览刷新。
- 保存后项目签名更新。
- 缓存自动失效。
- 不安全修改被诊断阻止。
- 关闭和回到时间线无状态丢失。

## 第四阶段：模型与能力中心

目标：用户可以自由配置任意模型和能力。

任务：

1. 定义模型配置数据结构。
2. 实现供应商适配器。
3. 实现凭据引用。
4. 实现能力映射。
5. 实现成本估算。
6. 实现权限策略。
7. 实现连接测试。

验收：

- 可配置至少一个云端供应商、一个私有网关和一个本地模型服务。
- 可为文本规划、代码生成、视觉理解、语音转文字绑定不同模型。
- 密钥不写入项目文件。
- 超预算任务需要确认。
- 模型不可用时有回退。

## 第五阶段：技能生成工作流

目标：用户能从主界面运行 HyperFrames 生成工作流并导入结果。

任务：

1. 技能注册表。
2. 技能推荐器。
3. 生成计划预览。
4. 任务队列。
5. 本地或远程执行器。
6. 输出目录规范化。
7. 导入预览。
8. 确认和回滚。

验收：

- 能生成动态图形片头。
- 能生成网站转视频项目。
- 能导入源链接组合。
- 有诊断时不能直接导入。
- 失败任务可重试或清理。

## 第六阶段：自然语言协作

目标：用户能用自然语言安全修改时间线和 HyperFrames 源文件。

任务：

1. 中文意图识别。
2. 项目上下文构建。
3. 动作计划。
4. 差异预览。
5. 用户确认。
6. 回滚。
7. 多轮上下文。
8. 诊断自动修复。

验收：

- 破坏性操作必须先展示差异。
- 确认后才写入。
- 每次写入都有回滚点。
- 模型输出不能直接写项目。
- 30 个常见对话场景通过。

## 第七阶段：预览、渲染和导出

目标：HyperFrames 片段完整参与 FreeCut 预览和导出。

任务：

1. 播放器桥。
2. 帧同步。
3. 渲染运行时检查。
4. 生产器任务。
5. 透明叠加。
6. 渲染缓存。
7. 音频策略。
8. 导出门禁。

验收：

- 预览、生产器和导出帧误差不超过 1 帧。
- 透明叠加可导出。
- 缓存签名失效正确。
- 缺少运行时时有明确引导。
- 导出失败不破坏项目。

## 第八阶段：安全、运维和发布

目标：达到可公开发布质量。

任务：

1. HTML 安全策略。
2. 模型隐私策略。
3. 密钥安全。
4. 审计日志。
5. 成本报表。
6. 支持排查材料。
7. 端到端测试。
8. 发布文档。

验收：

- 零 P0 和 P1。
- 用户文档、开发者文档、示例和常见问题完成。
- 主流程端到端通过。
- 性能门禁通过。
- 支持和回滚方案通过审查。

## 测试矩阵

| 范围 | 测试 |
| --- | --- |
| 数据模型 | 迁移、保存、重开、打包、解包 |
| 转换器 | 导出、导入、损失记录、性能预算 |
| 主界面 | 时间线动作、属性面板、项目库、右键菜单 |
| 工作室 | 文件读写、预览、保存、诊断、冲突 |
| 模型配置 | 连接测试、能力绑定、密钥引用、预算 |
| 技能任务 | 推荐、队列、失败、重试、导入预览 |
| 自然语言 | 意图识别、差异确认、回滚 |
| 渲染导出 | 运行时检查、帧同步、透明叠加、缓存 |
| 安全 | 脚本、路径、网络、隐私、凭据 |
| 发布 | 浏览器、性能、端到端、文档 |

## 工程门禁

每个阶段至少运行：

```bash
npm run check
npm run build
npm run test:run
```

涉及模块边界时增加：

```bash
npm run check:boundaries
npm run check:deps-contracts
```

涉及发布时运行：

```bash
npm run verify
```

如果本地环境缺少 Node、浏览器、FFmpeg 或渲染依赖，应记录为环境缺口，不能把未运行的验证写成已通过。

## 文档门禁

每个发布阶段必须更新：

- 用户指南。
- 开发者接口说明。
- 故障排查。
- 已知限制。
- 示例项目。
- 迁移说明。
- 发布说明。

文档必须与当前代码和数据模型一致。禁止继续传播旧的单 HTML 字符串、独立 `hyperframes-composition` 类型和未确认直接写入项目等过时设计。

## 完成定义

整个整合目标完成时，必须能证明：

1. 用户可以在 FreeCut 主界面中配置模型、运行生成、预览结果、导入时间线、继续编辑和导出。
2. HyperFrames 源项目目录完整保存并可重新打开。
3. 时间线上的 HyperFrames 片段和 FreeCut 原生片段可以混合编辑和导出。
4. 任意模型供应商、私有网关和本地模型可通过能力中心接入。
5. 所有 AI 写入都有预览、确认、来源和回滚。
6. 安全、隐私、成本和渲染门禁可执行。
7. 端到端测试覆盖主要用户旅程。

## 开发落地补充：源码迁移实施批次

为了避免一次迁移全部 HyperFrames 源码导致不可控，建议把源码级集成拆为十个可提交批次。

| 批次 | 目标 | 主要文件来源 | 验收证据 |
| --- | --- | --- | --- |
| 1 | 建立源码镜像目录和 provenance | 新建 `hyperframes-runtime` | `upstream-manifest.json`、import 规则、空 adapter 测试 |
| 2 | 迁移 parsers 和 lint | `packages/parsers/src`、`packages/lint/src` | HTML 解析、GSAP 解析、项目 lint 测试通过 |
| 3 | 迁移 core 浏览器运行时子集 | `packages/core/src/runtime`、`compiler` | 组合变量、时间线、runtime 注入测试通过 |
| 4 | 迁移 player | `packages/player/src` | FreeCut 预览器能加载项目目录并 seek 到指定帧 |
| 5 | 建立 Studio 最小工作室 | `packages/studio/src/components/nle`、`SourceEditor`、`FileTree` | 双击片段打开工作室、保存文件、预览刷新 |
| 6 | 接入 studio-server helpers | `packages/studio-server/src/helpers`、必要 routes | 安全路径、source mutation、thumbnail、selection adapter 测试 |
| 7 | 迁移 Studio 高级编辑 | DOM overlay、PropertyPanel、Layers、manual edits | 点击元素、修改属性、生成 patch、可撤销 |
| 8 | 迁移技能资源和执行器 | `skills/*`、CLI skills/registry 逻辑 | 技能目录展示、计划生成、任务输出归一化 |
| 9 | 迁移 producer-node | `packages/producer/src` | 本地运行时检查、渲染 job、透明输出小样 |
| 10 | 完成端到端体验 | FreeCut UI、模型中心、导出门禁 | 从生成到编辑到导出的 E2E 通过 |

每个批次都要单独提交，提交说明中写清楚：

- 迁移了哪些 HyperFrames 上游路径。
- 改写了哪些 import。
- 新增了哪些 FreeCut adapter。
- 哪些上游测试被移植或改写。
- 哪些能力暂未启用但源码已镜像。

### 文档完成门禁

本目录文档后续每次更新都要回答四个问题：

1. 这个能力的 HyperFrames 源码来源是哪一个包、哪一个目录或文件。
2. 迁移到 FreeCut 后放在哪个运行时目录。
3. 与 FreeCut 主界面的适配边界是什么。
4. 开发完成后用什么测试证明它可用。

### 代码完成门禁

代码实现达到可合并状态必须满足：

- 不新增 `@hyperframes/*` 运行时 npm 依赖。
- `src/features/hyperframes-runtime/upstream` 的来源可追溯。
- 浏览器 bundle 不包含 Node-only producer、FFmpeg、Puppeteer、Hono 服务端入口。
- Player、Studio、Studio Server、Producer、Skills 至少各有一个 FreeCut 集成测试。
- 任意模型配置至少覆盖云端、私有网关、本地 HTTP 三种 provider。
- 生成、导入、打开工作室、保存、预览、渲染、导出、回滚形成一条端到端用例。
