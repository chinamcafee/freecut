# 生成工作流与技能编排

## 本章目标

本章定义用户从自然语言、模板、素材或网页生成 HyperFrames 视频内容的完整工作流。它覆盖意图识别、技能选择、任务队列、模型调用、项目目录生成、校验、导入预览、确认、回滚和重试。

## 技能体系定位

HyperFrames 提供的技能体系是面向 AI 代理的视频生产知识库和工作流集合。FreeCut 集成时不应直接把技能暴露成命令行列表，而应包装成主界面中的生成能力。

建议内置技能分类：

| 分类 | 典型能力 |
| --- | --- |
| 营销生成 | 产品发布视频、网站转视频、品牌宣传 |
| 内容解释 | 无人讲解视频、文档转视频、代码变更说明 |
| 视频包装 | 嵌入字幕、说话人重剪、动态图形、片头片尾 |
| 音乐驱动 | 音乐视频、节奏同步、歌词动画 |
| 幻灯片 | 演示文稿、分段展示、互动式讲解 |
| 通用视频 | 多场景自由创作、循环动画、社交短片 |
| 领域工具 | 组合规范、动效、关键帧、媒体、注册表、命令行 |

## 意图识别

意图识别输出必须是结构化对象：

```ts
interface GenerationIntent {
  kind:
    | 'new-video'
    | 'timeline-insert'
    | 'overlay'
    | 'caption-package'
    | 'recut'
    | 'studio-edit'
    | 'timeline-edit'
  targetRange?: { startFrame: number; endFrame: number }
  selectedItemIds?: string[]
  desiredDurationFrames?: number
  resolution?: { width: number; height: number }
  language?: string
  styleRefs?: string[]
  requiredCapabilities: string[]
  candidateSkills: Array<{ skillId: string; score: number; reason: string }>
}
```

识别依据：

- 用户文本。
- 当前选区。
- 时间线播放头。
- 项目画幅。
- 素材类型。
- 历史偏好。
- 当前模型配置。

## 工作流计划

每次生成都应先生成计划：

```ts
interface GenerationPlan {
  id: string
  title: string
  steps: Array<{
    id: string
    type:
      | 'collect-context'
      | 'analyze-media'
      | 'call-model'
      | 'run-skill'
      | 'write-project-files'
      | 'lint'
      | 'preview'
      | 'render'
      | 'prepare-import'
    dependsOn?: string[]
    modelCapability?: string
    estimatedCost?: number
    userVisible: boolean
  }>
  importStrategy: 'source-link' | 'source-link-with-approximations' | 'rendered-media'
  requiresNetwork: boolean
  requiresPaidModel: boolean
  requiresRenderRuntime: boolean
}
```

用户确认计划后才能进入执行。

## 任务队列

生成任务使用队列模型，状态包括：

- 排队。
- 运行。
- 完成。
- 失败。
- 取消。
- 超时。

任务对象至少记录：

- 任务编号。
- 技能编号。
- 用户输入。
- 模型配置。
- 尝试次数。
- 当前阶段。
- 日志。
- 输出目录。
- 诊断。
- 清理要求。

当前 `HyperFramesSkillsJobRunner` 已提供基本队列、重试、失败、取消和超时状态，可扩展为持久化队列。

## 执行环境

### 浏览器轻量环境

可执行：

- 文本规划。
- 模板选择。
- 文件预览。
- 浏览器校验。
- 不需要本地生产器的草稿任务。

不可执行：

- 需要本地文件系统完整访问的技能。
- 需要 Chrome 与 FFmpeg 的生产渲染。
- 需要本地命令行的复杂工作流。

### 本地服务环境

可执行：

- 技能运行。
- 项目脚手架。
- 网页抓取。
- 转写。
- 文件复制。
- 生产器渲染。
- 自动诊断。

### 远程服务环境

可执行：

- 多用户队列。
- 高并发渲染。
- 云端模型调用。
- 团队素材检索。
- 成本和审计集中管理。

## 输出项目目录

技能输出必须被规范化为 HyperFrames 项目目录：

```text
manifest.json
index.html
compositions/main.html
assets/
metadata/provenance.json
metadata/diagnostics.json
```

规范化步骤：

1. 补齐清单。
2. 规范入口文件。
3. 把主组合路径写入 `activeCompositionPath`。
4. 扫描资产引用。
5. 计算文件和资产哈希。
6. 记录来源、模型、提示词和任务编号。
7. 运行校验。

## 校验与导入预览

任何任务输出都必须先进入导入预览。

导入预览包含：

- 项目名称。
- 缩略图。
- 文件树。
- 资产列表。
- 诊断列表。
- 不支持特性。
- 模型和费用摘要。
- 建议导入策略。

如果存在阻塞诊断，则禁止确认导入。阻塞诊断包括：

- 缺少入口文件。
- 缺少活动组合文件。
- 不安全脚本。
- 不安全事件属性。
- 资产路径越界。
- 清单不合法。
- 生成结果为空。

## 导入策略

### 源链接导入

创建一个 FreeCut `composition` 时间线项，并写入 `compositionLinks`。这是默认策略。

适合：

- 动态图形。
- 复杂 HTML 动画。
- 需要继续在工作室编辑的生成结果。

### 源链接加近似项

除源链接组合外，同时把可识别节点转换为 FreeCut 原生项。

适合：

- 文本较多。
- 视频和音频素材结构清晰。
- 用户需要快速改文案或媒体位置。

注意：近似项不是权威源。权威源仍是 HyperFrames 项目目录。

### 渲染媒体导入

先渲染为视频或透明叠加，再作为普通媒体导入。

适合：

- 用户只想使用最终效果。
- 项目需要稳定播放。
- 目标设备无法实时预览复杂 HTML 动效。

## 确认和回滚

写入 FreeCut 项目前必须创建确认记录：

```ts
interface ImportConfirmation {
  previewId: string
  jobId: string
  confirmedAt: number
  confirmedByUser: boolean
  changes: Array<{ op: 'add' | 'replace' | 'remove'; path: string }>
  rollbackId: string
}
```

回滚必须覆盖：

- 新增时间线项。
- 新增组合链接。
- 新增清单记录。
- 新增项目目录。
- 新增渲染缓存。
- 新增媒体库条目。

## 重试策略

重试分为三类：

| 类型 | 策略 |
| --- | --- |
| 模型失败 | 更换回退模型或缩短上下文 |
| 技能失败 | 保留工作目录，带日志重试 |
| 校验失败 | 进入工作室修复或让模型根据诊断修复 |

自动重试不能无限进行。超过阈值后必须交给用户确认。

## 技能推荐

技能推荐器应考虑：

- 用户文本关键词。
- 当前素材类型。
- 选中片段类型。
- 时间线目标位置。
- 项目画幅。
- 历史选择。
- 模型能力。
- 是否允许网络。
- 是否允许付费。

推荐结果要解释原因，例如“因为输入包含网站地址，推荐网站转视频工作流”。

## 与 FreeCut 原生 AI 的协同

有些任务不需要 HyperFrames 技能，应优先使用 FreeCut 原生能力：

- 对已有视频转写。
- 对已有视频生成字幕。
- 场景检测。
- 素材语义搜索。
- 简单转场推荐。
- 简单导出预设推荐。

复杂片头、动态图形、网站转视频、产品视频和多场景解释视频再交给 HyperFrames。

## 生成质量门禁

生成结果至少通过：

1. 项目目录结构校验。
2. HTML 组合校验。
3. 资产引用校验。
4. 安全扫描。
5. 缩略图生成。
6. 预览可打开。
7. 导入预览可回滚。

高质量模式还应通过：

- 文本不溢出。
- 关键帧可寻址。
- 首尾帧正常。
- 透明背景检查。
- 渲染小样检查。

## 开发落地补充：技能源码迁移与执行器

HyperFrames 的 `skills/*` 应作为源码资源迁移到 FreeCut，而不是运行时读取外部仓库。推荐迁移到：

```text
src/features/hyperframes-runtime/upstream/skills/
  embedded-captions/
  faceless-explainer/
  figma/
  general-video/
  hyperframes-animation/
  ...
```

迁移后新增索引：

```text
src/features/hyperframes-runtime/bridges/skills-bridge/
  skillCatalog.ts
  skillRequirementParser.ts
  skillPromptAssembler.ts
  skillWorkspace.ts
  skillSandbox.ts
  skillOutputNormalizer.ts
  skillImportPreview.ts
```

### 技能目录解析

`skillCatalog.ts` 读取每个技能的：

- `SKILL.md`：能力说明、触发条件、工作流。
- `CATALOG.md`：可展示目录项。
- `references/*`：规则、审美、布局、动效、失败模式。
- `scripts/*`：可选本地工具。
- `examples/*`：示例 HTML 或资产。
- `themes/*`、`dna/*`：可选风格配置。

解析结果转成 FreeCut UI 可展示的 `HyperFramesSkillDefinition`：

```text
id
title
description
categories
inputRequirements
modelRequirements
toolRequirements
outputKind
estimatedCostClass
safeDefaultOptions
sourcePaths
```

### 执行器分层

技能执行不能直接在 UI 线程跑。建议分三类执行器：

| 执行器 | 适用任务 | 能力 |
| --- | --- | --- |
| `BrowserSkillExecutor` | 纯文本、轻量 HTML 生成、无文件系统需求 | 模型调用、内存项目目录、浏览器 lint |
| `LocalServiceSkillExecutor` | 需要文件系统、Chrome、FFmpeg、转写、截图 | 本地服务、producer、CLI 工具子集 |
| `RemoteSkillExecutor` | 大批量渲染、重模型、团队共享 | 远程队列、对象存储、权限审计 |

所有执行器输出必须归一化为：

```text
SkillOutputBundle
  projectDirectory
  manifest
  generatedFiles
  sourceAssets
  logs
  diagnostics
  modelUsage
  suggestedImportStrategy
```

### 脚本迁移策略

`skills/*/scripts` 中的脚本不能无条件在 FreeCut 里执行。迁移规则：

1. 纯数据处理脚本改写为 TypeScript service，并纳入测试。
2. 需要 Chrome、FFmpeg、Python 的脚本放入本地服务执行器。
3. Shell 脚本只作为参考，不直接从 UI 调用。
4. 每个脚本声明输入目录、输出目录、网络权限、最大运行时间和可取消能力。
5. 脚本输出进入临时工作区，只有通过校验和用户确认后才能导入项目。

### 与模型中心的关系

技能不选择供应商，只声明需求。模型中心返回 `ModelExecutionPlan` 后，技能执行器把不同步骤路由到不同模型。例如：

- 脚本大纲：文本推理模型。
- 视觉素材理解：视觉模型。
- HTML 动效生成：代码模型。
- 音频转写：本地转写或云转写。
- 质量复核：低成本文本模型。

### 失败恢复

每个技能任务需要保存：

- 输入快照。
- 计划快照。
- 模型调用摘要。
- 临时项目目录。
- lint 报告。
- 预览缩略图。
- 用户确认或拒绝记录。

失败后提供三种动作：

1. 用同一模型修复。
2. 切换模型修复。
3. 打开工作室手动修复。
