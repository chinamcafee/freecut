# 源码级迁移与包级集成细则

## 本章目标

本章把 HyperFrames 的包级能力拆成 FreeCut 可执行的源码迁移计划。核心原则是：可以从 `/Users/changzechuan/VideoAIEditProjects/hyperframes` 源码迁移的能力，不在 FreeCut 中直接依赖对应 npm 包。FreeCut 通过独立源码镜像层获得 HyperFrames 能力，再用 adapter 和 bridge 把能力接入主界面、项目系统、模型中心、任务队列和导出管线。

本章不复制上游源码，只标明源码来源、迁移目标、改写点、适配边界和测试要求。

## 目标目录

建议在 FreeCut 中新增：

```text
src/features/hyperframes-runtime/

  adapters/

    freecut-render/
    freecut-models/
    freecut-security/

    skills-bridge/
    render-bridge/
    model-bridge/

```

`upstream` 目录尽量保存上游源码结构，方便后续同步。`adapters` 和 `bridges` 才是 FreeCut 定制逻辑所在。

## 迁移清单

| 能力 | 上游源码 | 迁移目标 | 是否进入浏览器 bundle |
| --- | --- | --- | --- |
| 组合运行时 | `packages/core/src/runtime` | `upstream/core/runtime` | 是，受控注入 |
| HTML 编译 | `packages/core/src/compiler` | `upstream/core/compiler` | 部分进入，复杂编译可在本地服务 |
| HTML/GSAP 解析 | `packages/parsers/src` | `upstream/parsers` | 是 |
| 项目校验 | `packages/lint/src` | `upstream/lint` | 是，Node 规则走服务 |
| 播放器 | `packages/player/src` | `upstream/player` | 是 |
| Studio UI | `packages/studio/src` | `upstream/studio` | 是 |
| Studio 服务 | `packages/studio-server/src` | `upstream/studio-server` | 否，浏览器只用类型和 helper 子集 |
| 生产渲染 | `packages/producer/src` | `upstream/producer-node` | 否 |
| CLI 工具 | `packages/cli/src` 子集 | `upstream/cli-tools` | 否 |
| 技能资源 | `skills/*` | `upstream/skills` | 资源进入，脚本按环境隔离 |

## import 改写

迁移时执行 import 改写，避免 FreeCut 代码依赖上游包名：

| 上游写法 | 迁移后写法 |
| --- | --- |
| `@hyperframes/core` | `../core` 或本地 alias `@/features/hyperframes-runtime/upstream/core` |
| `@hyperframes/parsers` | `../parsers` |
| `@hyperframes/lint` | `../lint` |
| `@hyperframes/player` | `../player` |
| `@hyperframes/studio` | `../studio` |
| `@hyperframes/studio-server` | `../studio-server` |
| `@hyperframes/producer` | `../producer-node` |

业务层禁止写：

```text
import { StudioApp } from "@hyperframes/studio"
import "@hyperframes/player"
```

业务层应写：

```text
import { FreeCutStudioShell } from "@/features/hyperframes-runtime/bridges/studio-bridge"
import { HyperFramesPlayerHost } from "@/features/hyperframes-runtime/bridges/player-bridge"
```

## core 迁移

来源：

- `packages/core/src/runtime/*`
- `packages/core/src/compiler/*`
- `packages/core/src/core.types.ts`
- `packages/core/src/safePath.ts`
- `packages/core/src/registry/*`
- `packages/core/src/templates/*`

FreeCut 使用方式：

- runtime 用于 Player 和 Producer 一致性。
- compiler 用于预览前 bundling、子组合展开、资产路径处理。
- registry 用于 Studio blocks 和技能插入。
- safePath 作为项目路径安全的底层参考。

改写点：

1. 删除或隔离不适合浏览器主 bundle 的 Node-only 代码。
2. runtime 注入脚本由 FreeCut 的 `createPreviewDocument` 控制。
3. registry 安装必须走 `HyperFramesProjectRepository`，不能直接写磁盘。
4. core telemetry 需要接入 FreeCut 日志脱敏策略。

测试：

- 变量读取和校验。
- 子组合加载。
- 运行时时钟。
- 媒体播放和 volume envelope。
- HTML bundling 资产路径。

## parsers 迁移

来源：

- `packages/parsers/src/htmlParser.ts`
- `packages/parsers/src/gsapParser.ts`
- `packages/parsers/src/gsapWriterAcorn.ts`
- `packages/parsers/src/composition.ts`
- `packages/parsers/src/assets.ts`
- `packages/parsers/src/hfIds.ts`

FreeCut 使用方式：

- Studio 属性面板保存 DOM 和 GSAP 修改。
- 模型输出 HTML 后做结构解析和修复。

2. linkedom 或 DOMParser 使用由环境 adapter 提供。
3. 解析失败必须返回诊断对象，不直接抛到 UI。

测试：

- HTML roundtrip。
- GSAP parse/write parity。
- hf id 持久化。
- 资产路径提取。
- 复杂组合解析性能。

## 验收总表

源码级迁移完成后，必须能证明：

1. FreeCut 代码中没有新增运行时 `@hyperframes/*` npm 依赖。
2. 每个迁移包都有来源记录和 import 改写记录。
3. Player 能在 FreeCut 主预览器中播放项目目录。
4. Studio 能作为 FreeCut 浮层打开、编辑、保存和回滚。
5. Studio Server 能力通过 FreeCut adapter 提供，不绕过项目权限。
6. Producer 只在本地服务或远程服务运行，不进入浏览器 bundle。
7. Skills 能通过模型中心运行，并输出可导入项目目录。
8. 任意模型配置能参与技能、自然语言编辑和诊断修复。
9. lint、安全、成本和隐私门禁在导入、保存、预览、渲染、导出前生效。
10. 端到端流程可运行：配置模型、生成视频、预览、导入时间线、打开工作室、修改、渲染、导出、回滚。
