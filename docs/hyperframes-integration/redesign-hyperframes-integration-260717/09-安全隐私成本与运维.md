# 安全隐私成本与运维

## 本章目标

本章定义 HyperFrames 集成的安全边界、隐私保护、模型费用控制、日志审计、故障处理和运维要求。AI 生成视频涉及外部模型、脚本、素材、网页、渲染服务和本地文件，必须默认保守。

## 安全边界

系统包含四个风险边界：

1. 用户项目和本地素材。
2. HyperFrames HTML、脚本和资产。
3. 大模型和外部服务。
4. 本地或远程渲染运行时。

任何跨边界行为都必须有权限、日志和可撤销路径。

## HTML 安全

HyperFrames 项目本质是 HTML。进入 FreeCut 主预览前必须检查：

- 内联脚本。
- 事件属性。
- 外部网络资源。
- 不安全路径。
- 缺失组合文件。
- 可疑 iframe。
- 自动播放音频。

策略分三档：

| 档位 | 说明 |
| --- | --- |
| 严格 | 禁止脚本和外部网络，只允许受控属性和本地资产 |
| 标准 | 允许 HyperFrames 运行时和可信脚本，禁止任意外部网络 |
| 开发 | 允许更多脚本，但只在用户明确启用的工作室中运行 |

默认使用标准档。导入技能输出时先用严格档扫描，再根据需要请求用户放宽。

## iframe 沙箱

预览 iframe 必须默认沙箱化：

- 不允许顶层导航。
- 不允许弹窗。
- 不允许未授权下载。
- 不允许访问主窗口。
- 只允许必要脚本。
- 只允许同源或受控资源。

工作室调试模式可以临时开放更多能力，但必须明确标识。

## 模型隐私

发送给模型前需要做上下文裁剪：

- 只发送当前任务需要的项目摘要。
- 默认不发送完整素材路径。
- 默认不发送完整源代码。
- 默认不发送用户本地绝对路径。
- 对日志、密钥、邮箱、网址令牌做脱敏。
- 大文件通过摘要或用户确认后上传。

用户应能按项目设置：

- 是否允许发送截图。
- 是否允许发送音频。
- 是否允许发送视频帧。
- 是否允许发送源码。
- 是否允许远程渲染。
- 是否允许网页抓取。

## 凭据安全

密钥必须存放在系统安全存储或远程密钥服务中。项目文件只保存引用。

日志中禁止出现：

- 原始密钥。
- 授权令牌。
- 完整请求头。
- 未脱敏用户隐私。
- 未脱敏模型响应。

## 成本控制

成本控制分三层：

1. 单次任务预算。
2. 项目预算。
3. 用户或团队预算。

所有付费任务开始前必须展示：

- 预计调用模型。
- 预计输入输出规模。
- 预计费用区间。
- 超预算处理方式。
- 是否可能触发渲染费用。

任务运行中需要累计费用。超过阈值必须暂停并请求确认。

## 审计记录

每次 AI 和渲染行为都记录：

- 用户动作。
- 时间。
- 模型配置引用。
- 技能编号。
- 任务编号。
- 输入哈希。
- 输出哈希。
- 费用估算。
- 写入差异。
- 确认记录。
- 回滚编号。

审计记录应可导出，用于团队支持和问题复现。

## 运维监控

本地模式需要监控：

- 模型连接状态。
- 本地服务状态。
- Chrome 可用性。
- FFmpeg 可用性。
- 存储配额。
- 渲染队列。
- 缓存体积。

远程模式还需要监控：

- 队列延迟。
- 渲染失败率。
- 模型错误率。
- 平均费用。
- 并发数。
- 节点健康。
- 下载失败率。

## 故障处理

支持排查时必须收集：

- 浏览器版本。
- 项目类型。
- 媒体详情。
- HyperFrames 项目路径。
- 技能任务编号。
- AI 来源编号。
- 渲染设置。
- 导出设置。
- 诊断结果。
- 回滚编号。

## 发布前阻塞项

以下问题必须阻塞发布：

- 数据丢失。
- 无法回滚破坏性 AI 操作。
- 不安全脚本可直接进入主预览。
- 密钥写入项目文件。
- 阻塞诊断仍允许导出。
- 渲染失败无错误信息。
- 模型费用无预算或确认机制。
- 删除项目目录时误删仍被引用内容。

## 用户可见支持信息

错误信息必须可操作，例如：

- “缺少 FFmpeg，无法渲染透明叠加。请安装 FFmpeg 或切换远程渲染。”
- “此生成结果包含不安全脚本，已阻止导入。可打开工作室查看并修复。”
- “当前模型不支持图像输入，请切换视觉模型或改用文本描述。”
- “该 HyperFrames 项目仍被 3 个时间线片段引用，不能删除。”

## 数据保留策略

建议默认：

- 任务日志保留 30 天。
- 渲染缓存按空间自动清理。
- 失败任务工作目录保留 7 天。
- 成功导入的源目录随项目长期保存。
- 密钥只保留在用户或团队密钥存储。

用户应能手动清理：

- 渲染缓存。
- 缩略图缓存。
- 失败任务目录。
- 模型调用日志。
- 未引用 HyperFrames 项目。

## 开发落地补充：源码级安全边界

源码迁移会把更多能力放进 FreeCut 仓库，因此安全边界必须比 npm 依赖模式更清楚。

### 迁移源码安全分级

| 分级 | 目录 | 允许环境 | 安全要求 |
| --- | --- | --- | --- |
| 浏览器安全 | `upstream/player`、`upstream/parsers` 的安全子集 | 主窗口或 iframe | 禁止直接文件系统、禁止任意网络、禁止 eval |
| 沙箱预览 | `upstream/core/runtime`、组合 HTML | iframe sandbox | CSP、资源白名单、postMessage 协议校验 |
| 工作室编辑 | `upstream/studio` | 主窗口受控浮层 | 只通过 adapter 读写项目，隔离快捷键和样式 |
| 本地服务 | `upstream/studio-server`、`producer-node`、`cli-tools` | Node 本地服务 | 路径白名单、端口绑定、认证 token、日志脱敏 |
| 技能执行 | `upstream/skills` | 任务沙箱 | 工具权限、网络权限、时间限制、输出校验 |

### 路径和文件写入

所有来自 Studio、模型、技能和本地服务的写入必须经过统一函数：

```text
assertHyperFramesProjectPath(projectId, relativePath)
assertWritableFileType(relativePath, mime)
createWritePlan(before, after, provenance)
runContentGuards(writePlan)
commitWritePlan(writePlan)
```

禁止：

- 写入 FreeCut 项目目录外部。
- 写入 `.env`、密钥文件、系统路径。
- 通过符号链接逃逸项目目录。
- 从模型响应中直接执行 shell 命令。
- 在主窗口执行生成项目内的任意脚本。

### postMessage 协议

Player、Studio iframe 和组合运行时之间必须定义显式协议：

```text
HyperFramesRuntimeMessage
  type
  projectId
  compositionPath
  frame
  payload
  nonce
```

接收端校验：

1. `origin` 或 sandbox token。
2. `nonce` 是否属于当前预览会话。
3. `projectId` 是否匹配当前打开项目。
4. message type 是否在白名单。
5. payload 是否符合 schema。

### 模型隐私

模型中心在调用前要生成素材访问清单：

- 文本 prompt。
- 被上传的图片、视频、音频和项目文件。
- 是否包含本地路径或用户隐私信息。
- 是否会发送到云端。
- 预计费用。

用户选择本地隐私模式时，技能只能使用本地模型和本地工具；如果缺少能力，系统提示能力不足，而不是自动降级到云端。

### 运行时维护

源码镜像层要有升级流程：

1. 记录当前 HyperFrames 本地源快照。
2. 对比 `upstream-manifest.json`。
3. 更新镜像目录。
4. 重新执行 import 改写。
5. 跑迁移包自带测试和 FreeCut 集成测试。
6. 更新 `patch-notes.md`。

如果上游源码发生大改，FreeCut 的 adapter 合约必须优先保持稳定，不能让上游 UI 变化直接破坏 FreeCut 主界面。
